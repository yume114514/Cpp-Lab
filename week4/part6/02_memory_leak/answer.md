# 6-18 `new` 之后没有 `delete`（内存泄漏）

## 题目

下列程序有何问题，请改正。

```cpp
#include<iostream>
using namespace std;
int fn1(){
int *p=new int(5);
return *p;
}
int main(){
int a=fn1();
cout<<"the value of a is:"<<a;
return 0;
}
```

题目原程序见 [original.cpp](original.cpp)，改正后的程序见 [main.cpp](main.cpp)。

## 一、现象

- 编译：通过，`-Wall` 一条警告都没有（编译器看不出这个问题）。
- 运行：输出 `the value of a is:5`，退出码 0，**看起来完全正确**。
- 所以这是「结果对、资源错」的问题，靠看输出发现不了。

## 二、根因

**内存泄漏**（memory leak）：`fn1` 里用 `new int(5)` 在堆上申请了一块内存，函数从头到尾没有
`delete`，就把它的地址弄丢了。

关键在于 `p` 是什么：`p` 是一个**局部指针变量**，它自己活在 `fn1` 的栈帧里，函数一返回，
`p` 这个变量就销毁了。`p` 里存着的那个堆地址也随之消失，那块堆内存从此没有任何指针指着它，
程序再也无法 `delete` 它 —— 这块内存就一直被占着，直到进程结束。

`return *p;` 返回的是 `*p` 这个 **int 值（5）的拷贝**，不是地址。所以调用方拿到 5，
和那块内存还不还得回去，是两件完全不相干的事。

## 三、定量：漏了多少

`new int(5)` 一次占 4 字节（`sizeof(int)`），加上堆分配器自身的块头开销，实际每泄漏一次大约
十几个字节。这个程序只调用一次，漏 4 字节，完全看不出来；放进循环里就露馅了。

实测（同一台机器、同一份循环代码，只差一个 `delete`，各循环 500 万次，采样进程峰值内存）：

| 版本 | 循环 500 万次后的输出 | 进程峰值内存 |
| --- | --- | --- |
| 无 `delete`（题目原版） | `sum = 25000000` | **76.3 MB** |
| 有 `delete`（改正版） | `sum = 25000000` | **4.2 MB** |

两者输出一模一样，内存差了 18 倍。差值约 72 MB ÷ 500 万次 ≈ 每次 15 字节，
其中 4 字节是 `int` 数据本身，其余是分配器的块头。

## 四、改正

### 改法一：最小改动，把 `delete` 补上（推荐，保留原题意）

先在 `delete` 之前把值取出来，再释放，再返回：

```cpp
int fn1(){
    int *p = new int(5);
    int value = *p;     // 先把值取出来
    delete p;           // 再释放内存
    return value;       // 最后返回值
}
```

顺序不能反：`delete p;` 之后 `*p` 已经不能再读了（那块内存已归还，再读是未定义行为），
所以必须「先取值，后 delete」。

### 改法二：根本不需要 `new`

如果只是想返回一个 5，堆内存完全用不上，放栈上就行，连 `delete` 都不用写：

```cpp
int fn1(){
    int x = 5;
    return x;
}
```

### 通用规则

- **谁 `new` 谁 `delete`，`new` 和 `delete` 必须配对**；
- 函数里 `new` 出来的东西，如果地址不交给调用方，就必须在本函数内 `delete`；
- 如果地址要交给调用方（返回指针），那要把「用完必须 delete」写进约定，让调用方负责。

## 五、作业里可以直接用的表述

> 问题：`fn1` 中 `new int(5)` 申请了堆内存，却没有对应的 `delete`。函数返回时只把 `*p` 的值
> 拷给 `a` 返回，局部指针 `p` 随函数结束而销毁，堆上那块内存的地址彻底丢失，再也无法释放，
> 造成内存泄漏。因为返回的是值的拷贝，所以程序输出仍然正确（5），错误不会体现在结果上；
> 但每调用一次就泄漏一块内存，用循环反复调用会持续占用内存直至耗尽。
>
> 改正：在 `delete` 之前先把 `*p` 存入一个局部变量，`delete p;` 之后再返回该变量；
> 或者干脆不用 `new`，直接 `int x = 5; return x;`。
