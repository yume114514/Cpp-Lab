# 6-17 指针未初始化就解引用（野指针）

## 题目

下列程序有何问题，请仔细体会使用指针时应避免出现这个问题。

```cpp
#include <iostream>
using namespace std;
int main(){
    int *p;
    *p=9;
    cout<<"the value at p:"<<*p;
    return 0;
}
```

## 一、现象

- 编译：成功（只有一条 warning，见下）。
- 运行：本机 `-O0` 下每次都打印 `the value at p:9`，退出码 0；换 `-O2` 每次崩溃，
  退出码 `-1073741819`（即十六进制 `0xC0000005`，访问冲突 / 段错误）。

## 二、根因

`p` 没有初始化就解引用（第 4、5 行）。`int *p;` 只是声明了一个用来存放地址的变量，
没有给它任何初值，`p` 里是栈上的随机残留值，这样的指针叫**野指针**。
`*p=9;` 的含义是「把 9 写入 `p` 里存的那个地址指向的内存」，于是 9 被写到了一块
不知道属于谁的内存里，属于**未定义行为**（undefined behavior）。

## 三、机制

### 1. 为什么编译能过

编译期只做类型检查：`p` 是 `int*`，`*p` 是 `int`，给 `int` 赋 `9` 语法完全合法。
标准没有规定「指针未初始化就编译不过」。编译器实际给出了警告，但是 **warning 不是 error**：

```text
warning: 'p' is used uninitialized [-Wuninitialized]
    5 |     *p=9;
      |     ~~^~
note: 'p' was declared here
    4 |     int *p;
```

### 2. `*p=9` 到底做了什么（反汇编）

```asm
movq   -8(%rbp), %rax      ; 把栈上 -8(%rbp) 的 8 字节读进 rax，那就是 p 的值
movl   $9, (%rax)          ; 把 9 写进 rax 指向的那块内存，这就是 *p=9
```

可见 `*p=9` 并没有「把 9 存进 p」，而是**把 9 存进 p 里记录的那个地址**。
`p` 里是什么垃圾值，9 就落到哪里，程序完全失控。

注意：这段机器码是「编译之后生成的东西」，它不能成为「编译能过」的原因。
编译通过的原因是上面的类型检查。

### 3. 为什么这台机器上没崩

因为那块栈内存恰好可写。同一份代码只改优化等级：

| 编译参数 | 运行 3 次结果 |
| --- | --- |
| `-O0` | 每次都输出 `the value at p:9`，退出码 0 |
| `-O2` | 每次都崩溃，退出码 `-1073741819`（`0xC0000005`） |

标准不规定未定义行为的结果，所以「碰巧对了」和「直接崩溃」都算正常表现。
本次打印出 9 只是运气，不是程序正确。

## 四、避免方法

指针在定义时就给它一个确定的地址：

```cpp
int x = 0;
int *p = &x;        // 指向一个真实存在的变量
```

或者用动态分配并记得释放：

```cpp
int *p = new int(0);
// ...
delete p;
p = nullptr;
```

或者先置 `nullptr`，解引用前一定先判断：

```cpp
int *p = nullptr;
if (p != nullptr) { *p = 9; }
```

## 五、作业里可以直接用的表述

> `int *p;` 只声明了一个用来存放地址的指针变量，没有给它初值，`p` 里是栈上的随机值，
> 是野指针。执行 `*p=9;` 时，程序把这个随机值当成地址去写入，等于往一块不知道属于谁
> 的内存里写数据，属于未定义行为：可能崩溃，可能悄悄改坏其他变量，也可能像本例一样
> 恰好写到可写内存而输出 9。这种结果不可依赖，也无法靠编译器发现。
>
> 避免办法：指针定义时就初始化，例如 `int x; int *p=&x;`，或用 `new` 分配，或先置
> `nullptr` 再判断。

一句话总结：问题不是「`p` 没初始化所以编译不过」，而是「`p` 没初始化就解引用，
把 9 写到了一个不知道是哪的地址」。
